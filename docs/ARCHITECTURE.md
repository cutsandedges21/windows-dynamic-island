# Architecture

Working name: **Island** (identifier `com.moss.island`). The product name is still open.

```
Activities ──► Priority ──► Layout ──► Animation ──► Rendered pill
 (TS)          (TS)         (TS)        (TS springs)   (one DOM element tree)
   ▲
   │ typed commands + events (Tauri IPC)
   │
 Rust native layer: windows, monitors, processes, files, media, audio,
 power, network, clipboard, devices, Claude hook pipe, HTTP
```

## Windows

| Window | What it is |
|---|---|
| `island` | Transparent, borderless, always-on-top, non-activating tool window that covers the **work area** of the chosen monitor. The pill is drawn inside it with CSS transforms, so moving it between the four anchors is a spring animation inside one window, never an OS window move. Outside the pill the window ignores the mouse: a Rust thread polls the cursor and toggles click-through against the hit rect the island publishes. |
| `app` | A normal window (Mica) with three pages: **Activities**, **Workspaces** and **Settings**. Opened from the tray, the island's quick menu, or `Alt+Shift+A`. |

Decisions Moss made during the build (they override the spec where they differ):

- **Tap outside → resting size.** Any press outside the pill (reported by the Rust poll thread, or a press on the window's transparent margin) closes views, clears surfaced events and the inline input, and dismisses urgent cards. A dismissed permission card is declined, so the terminal asks immediately instead of waiting out the hook timeout.
- **Vertical on the sides.** Left/right pills stand vertical: length along the edge (level percentages of the work-area height), thickness growing inward. Text stays upright; segments stack top to bottom (`fitVertical`). The pill turns horizontal only while an inline input is open.
- **Peek behind.** A tap of Ctrl alone with the pointer on the pill (pressed and let go within 0.6 s, no other key with it) fades the island and lets clicks through until the pointer leaves (`overlay.rs` poll loop). Ctrl+V, Ctrl+C and the like are shortcuts, not taps, and while the island takes the keyboard Ctrl is for what is typed, so pasting into a card never makes the island vanish (Moss, 2026-10-16).
- **Hide for a while.** Right-click the pill › Hide (or the tray, or Settings › Behavior): 30 minutes, 1 hour, 3 hours, until tomorrow morning (the next 6 AM at least an hour away) or until shown again. `island.hiddenUntil` is saved, so a hide outlasts a restart (a notification says so at startup); the window, the bot and every Duplicate copy hide (`island_show`). The toggle hotkey or the tray brings it back. While hidden, Claude's permission prompts go back to the terminal at once, chats do not wait for a reply, and Land declines offers.
- **No flip on time.** Clocks, timers and counters update in place (`timeLike()` in the renderer); only wording changes roll.

- **The card under the pill.** Anything longer than one row (a chat's last message and a reply box, a permission's full command, Claude's questions, limits and sessions on hover, the grid of everything that is on) goes in a card attached to the pill on the side it grows towards (`sheet.ts`). Hovering an activity's chip asks that activity for its card, so Claude's sessions, limits and tokens show on hover instead of behind a "…" screen.
- **Everything at a glance when open.** Tapping the island opens a Control-Center grid: one tile per switched-on activity (`Activity.tile()`), plus the island's own Day tile.
- **Arranged like iOS Control Center.** The grid is four cells across and four down per page, invisible except while arranging (empty cells then show faintly). Long-press a tile (or an empty spot) to arrange; still holding, the same press carries the tile. A tile lands on the exact cell it is dropped on, leaving empty cells before it if dropped past the others; dropped onto tiles, it goes in front and they move on; its old spot closes up. Dragging a tile's corner arc resizes it (1x1, 2x1, 1x2, 2x2; lists, cards and players two wide at least). Holding a carried tile at the card's side for two seconds turns the page; past the last page it makes a new one, and a page left empty goes on the drop. Layout rules: `grid.ts` (`moveTile`, `settle`), saved as `island.grid.pages` (tile keys per page, `null` for an empty cell the user left).

- **The bot lives beside the pill.** A round bubble left of the pill (above it on the side edges, `bubbleRect`) holds the bloub bot (`src/fx/bot`) in the user's accent (`botColors` picks the eye colour with more contrast), on the pill colour. It stays where the pill rests, so it shows when the idle pill tucks away. Its eyes rest in the middle; a pointer within 110 px pulls them a little (`src/core/gaze.ts`, the pointer from Rust's overlay poll). Settings › Appearance › Bot. Spec: `docs/superpowers/specs/2026-10-09-island-bot-design.md`.
- **It reacts to everything.** Each activity reports through `Activity.pet()` (`BaseActivity.saw()` for moments). The brain (`src/core/pet.ts`) picks the highest mood (Quiet adds asleep; the bot's own chat beats all) and plays the newest moment over it; repeats on one key merge, Quiet lets only urgent moments through, late at night it yawns. `src/core/looks.ts` turns that into a bloub pose, one of its 16 faces, costume pieces (`src/fx/bot/costumes.ts`) and a CSS motion. The island asks on every compose and once a second. `/?pet` in the browser preview plays every look.
- **It is the AI, and the only way to ask.** A click on the bot opens a thin bar under the bot and the pill (`ChatBar`, `chatBarRect`; the island does not open); the answer drops into a card past it. Local AI is that chat's brain (`chat()`) and has no pill, card, tile or home button of its own: only a model downloading shows in the pill (Moss, 2026-10-16: keep only the bot as the way in). The bar's Local | Claude switch sends to Claude instead, through Claude Code or an API key, chosen in Activities › Bot chat (the `local` entry; Ask Claude's own activity went in 0.3.0, and `ask.ts` keeps only the backend choice). How long the local model takes is learned per model and shows under Thinking… as "~5 s".

The island only takes keyboard focus while an inline input is open (Continue Session, Ask), or after the user clicks into an input on the card. Rust then drops `WS_EX_NOACTIVATE`, activates the window, and on release restores the window that had focus before. A card never takes focus by itself, so it cannot steal keystrokes from whatever the user is typing in. Those style bits survive tao: tao rebuilds a window's extended style from its own flags on every click-through toggle, show and hide, with `WS_EX_APPWINDOW` and without `WS_EX_TOOLWINDOW`, which put the island back in Alt-Tab and let a click on the pill take the focus (found 2026-10-15, live style 0x40118). `keep_style` (a window subclass in `overlay.rs`) corrects every change on its way in (`WM_STYLECHANGING`), for the island and its mirrors.

## TypeScript core (`src/core`)

| Module | Job |
|---|---|
| `spring.ts` | Exact damped-spring solver (SwiftUI-style `response` + `damping`). Retargeting keeps velocity, which is what makes interrupted motion look physical. |
| `animator.ts` | One `requestAnimationFrame` loop for every spring in the app. It stops when everything has settled, so an idle island costs zero frames. |
| `layout.ts` | Island geometry from work area, anchor, level and width percentages. The anchor gives an **expansion vector**: top grows down, bottom grows up, left grows right, right grows left. Text never rotates. |
| `segments.ts` | The content model. An activity describes its pill content as a list of keyed segments (icon, dot, text, progress, button, chip, input, meter…). The fitter measures them with canvas `measureText` (no DOM layout), drops low-priority segments and truncates text to fit the space budget. |
| `renderer.ts` | Keyed DOM renderer. Matching keys spring to their new x and width; new segments blur-fade in, removed ones blur-fade out; changed text rolls. Only `transform`, `opacity`, `filter` and the shell's size animate. |
| `sheet.ts` | The card under the pill. Typed blocks (header, wrapped text, code, buttons, input, meter, rows, choices, stats, countdown, tile grid), keyed like segments; unchanged blocks are left alone, inputs and meters are patched in place. Its height springs to the content and its position rides the pill's frames. Activity text only ever goes in through `textContent`. |
| `grid.ts` | The Control Center's layout as data: pages of tile keys and empty cells, packed first-fit per page, overflow to the next page. `moveTile` (drag and resize), `settle` (tidy and place), `withNew` (new tiles next to their neighbour in the activities order). |
| `island.ts` | The island engine: picks the primary activity, the level (idle, compact, expanded, maximum), secondary chips and overflow, hover, open/closed, transient surfacing, interrupts, quick menu, inline input focus. |
| `priority.ts` | Ranking: band (high, medium, low) and manual order, plus foreground or background weight and interrupts. |
| `activity.ts` | The Activity contract and registry. Built-in and external activities use the same contract. |
| `bus.ts` | Typed event bus inside a window. |
| `settings.ts` | The settings schema and defaults. Rust persists them (`settings.json`) and broadcasts every change to both windows. |
| `native.ts` | Typed wrappers for every Rust command and event, plus a browser mock so `npm run dev` previews the island in a normal browser. |

## Activities (`src/activities`)

Each activity owns its state, reads native data through `native.ts`, and renders `compact`, `expanded` and `maximum` segment lists. Behaviour flags per activity: enabled, priority, auto-show, persistent, interactive, interrupt.

Claude (`src/activities/claude`) is a TypeScript port of Usage Clip (`claude-session-monitor`):

| Usage Clip module | Here | Notes |
|---|---|---|
| `registry.js`, `paths.js`, `status.js`, `transcript.js`, `procinfo.js`, `tracker.js`, `history.js`, `tokens.js`, `usage.js`, `desktop-chats.js` | same names, `.ts` | Logic ported as is, unit tests ported to Vitest. File and process access goes through small Rust primitives (`fs_read_tail`, `fs_scan_lines`, `proc_snapshot`, …). |
| `focus.js`, `platform/win32.js` | `focus.ts` + Rust `procs.rs` | Window activation keeps the foreground-lock escalation (plain request, AttachThreadInput, synthetic Alt). |
| `usage.js` HTTP | Rust `claude_usage_fetch` | The OAuth token is read and used in Rust and never enters the webview. |
| tray, hotkeys `Alt+Shift+1–9`, `Alt+Shift+0`, toasts | Rust `tray.rs`, `hotkeys.rs` + TS | Same behaviour. |

New on top of Usage Clip:

- **Hooks** (from Coucou, MIT): `island-hook.exe` is registered as a Claude Code hook for each event. It forwards the event over `\\.\pipe\island-<user SID>`. Three wait for the island: `PermissionRequest` (Allow, Deny, Deny with a reason), `PreToolUse` for `AskUserQuestion` (questions, below) and `Stop` (the reply window, below). If the island is closed or doesn't answer in time, the hook prints nothing and Claude Code carries on as if Island were not installed. Installing shows a diff of `~/.claude/settings.json` and takes a dated backup first; nothing is written without a click (or `Island.exe --install-hooks`).
- **Questions before they are asked.** The VS Code extension shows its own question box beside a `PermissionRequest` hook and keeps it: on 2026-10-16 Moss answered a question in the island, the hook delivered the answers, and the box stayed. So a question is answered in its `PreToolUse` instead, the documented way for tools that need the user: `permissionDecision: "allow"` with `updatedInput` (the questions as they came, plus `answers`). The island holds the question as a card (`PermissionCard.early`) unless its chat's window is in front, which passes it at once (like the reply window); switching to that window lets it go too. A `PermissionRequest` for a question already held is declined at once (`HookState.askedEarly`), so nothing is asked twice. The installer gives PreToolUse 120 s for this (every other tool passes straight through); an older install shows as out of date. A `PermissionRequest` question still works in the terminal for old installs.
- **The reply window.** When a chat finishes, its `Stop` hook asks the island whether to wait. The island answers within milliseconds: if the chat's own window is in front (and, when several chats share that window, it is the one last prompted) it passes at once; otherwise it shows the card with the chat's final message (`last_assistant_message`) and a reply box, and the chat waits `replyWindowSeconds` (45 s by default; clicking the box extends it to 4 minutes, never past 270 s). A reply typed there becomes `{"decision":"block","reason":…}`, which Claude Code documents as "keep going with this", so the reply lands in that same chat, editor or terminal. Switching to the chat's window, tapping outside the island, or a new prompt in the chat releases it immediately. If Claude Code stops waiting first, the pipe closes and the card goes.
- **Wire format.** The island answers a waiting hook with one word (`ack`, `ack:<ms>`, `hold:<ms>`, `allow`, `deny`, `pass`) or one JSON line (`{"kind":"reply","text"}`, `{"kind":"deny","message"}`, `{"kind":"answer","updatedInput"}`). Only `island-hook` turns these into Claude Code's JSON (`output_json` in `hook/src/main.rs`), so that format lives in one place.
- **Continue Session** (and replies typed after the reply window closed), through public mechanisms only:
  - editor chats (`claude-vscode`): the extension's own deep link, `<editor>://anthropic.claude-code/open?session=<id>&prompt=<text>`. The extension opens the chat with the text in its box but does not send it, so the text also goes on the clipboard and the island says to press Enter there;
  - live terminal chats: `island-hook.exe inject <pid>` attaches to the session's console and types the prompt plus Enter (`WriteConsoleInputW`);
  - closed terminal chats: `claude --resume <id> "<prompt>"` in a minimized console. The chat then shows up as live again, and its permission prompts reach the island through the hooks.

## Rust (`src-tauri/src`)

Rust is kept to native access: window styles and click-through, monitors and work areas, process table and window activation, file primitives, the hook pipe, GSMTC media, Core Audio volume and mic, power, CPU and memory, network throughput, clipboard and device messages (one message-only window), TCP listeners, HTTP GET, and settings persistence. Product logic stays in TypeScript.

- **Updates** (`updater.rs`). Only full releases (not pre-releases), and only signed ones: the release notes carry `<!-- island-signature: <base64> -->`, an Ed25519 signature by the key whose public half is `UPDATE_KEY`, over `island-update`, the version and the file's SHA-256, a line each (so an old file can't come back labelled as a newer version). One such comment per file of the release (Island.exe and Island.dmg); an update installs when any of them verifies the file it downloaded. `node scripts/sign-release.mjs <version> [files]` prints the lines (`release/Island.exe` when no file is given), with the private key in `%USERPROFILE%\.island\update-signing-key.pem` (never in the repo, which is public). Without that key no Island updates itself again; it must be backed up. Someone who gets into the GitHub account can still publish a release, but no Island installs it. Windows swaps exes (the running one becomes `Island.old.exe`). A Mac installs the release's `Island.dmg` (`install_dmg`): `hdiutil attach -nobrowse -readonly` at a private mount point, `ditto` of its Island.app to `Island.app.new` beside the installed app, installed → `Island.old.app`, new → `Island.app` (put back if that fails), detach, then `open -n` the app with `--after-update`, which waits for the old process with `kill(pid, 0)`; the next start deletes `Island.old.app`. A Mac Island running from the disk image (`/Volumes/`) or translocated (never moved out of Downloads, `/AppTranslocation/`) downloads nothing and says once per release to move Island to Applications; a failed install says once to allow Island in Privacy & Security › App Management or to download the new dmg.
- **Files the webview may read** (`fsx::allowed`): inside the user's profile folders only; the root itself or below it (not a sibling like `Downloads2`), and never through a link or junction below the root.
- **HTTP GET** (`web.rs`, one client for Windows and the Mac): https only, and the body stops at its cap as it arrives.
- **Battery** (`system.rs`): "Full in 40 min" while charging, from what Windows says comes in (mW) and is stored (mWh), smoothed; the percentage gives what a full battery holds today. On battery Windows' own estimate ("2 h 10 min left") as before.
- **Crashes** (`crash.rs`, first thing in `run()`). A release build aborts on a panic, which used to leave nothing in island.log. The panic hook, and on Windows an unhandled-exception filter for crashes in native code, write a `crash:` line (thread, place and message; or the exception code at `module+offset`) without waiting for the log's lock (`log::line_now`), leave `last-crash.txt`, and start a new Island with `--after-crash <pid>`, which waits up to a minute for the old process to be gone before the single-instance check. Not when Island ran under a minute, or under ten minutes after starting from a crash, so a crash that keeps coming can't loop. The next start logs it and the pill says "Island restarted" (an `external-activity` note, like an update's). Windows' own `RegisterApplicationRestart` never restarted a test program on Windows 11 (2026-10-27), so Island doesn't use it. Uncaught JavaScript errors and rejections go to the log from `src/core/errors.ts` (once a minute each, 30 a run).
- **Lock keys** (`keys.rs`): a thread reads the Caps Lock and Num Lock toggles every 100 ms (`GetKeyState`'s low bit; the lock keys' state is the same for every program) and emits `lock-keys` on a change. A Mac reads Caps Lock from `CGEventSourceFlagsState` (`mac/input.rs`) and has no Num Lock.
- **Brightness** (`brightness.rs`): msgwin.rs registers its window for the power setting `GUID_VIDEO_CURRENT_MONITOR_BRIGHTNESS`. Windows answers at once with the brightness of the screen it controls, then on every change (keys, Quick Settings, the light sensor); `WM_POWERBROADCAST`/`PBT_POWERSETTINGCHANGE` → `brightness::report`, which emits `brightness` (0–100) when it changed; `brightness_get` for the island's start. External monitors don't report it.
- **Bluetooth battery** (`btbattery.rs`): the battery Settings › Bluetooth & devices shows is the device property `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2` on the device's node. SetupAPI over the BTHENUM and BTHLE enumerators reads it, the name and `DEVPKEY_Device_IsConnected` (`{83DA6326-…} 15`; the nodes stay present while disconnected); a device's profile nodes ("… Hands-Free AG", "… Stereo") merge into one by name, connected first, then the higher reading. About 5 ms.

### macOS

Windows code stays where it is. A module that is almost all Windows API has a Mac twin in `src-tauri/src/mac/<name>.rs`, swapped in by `#[cfg_attr(target_os = "macos", path = "mac/<name>.rs")]` on its `mod` line in lib.rs, with the same command names. Twins of features that come later return `Err("not on Mac yet")`; `native.ts`'s `call()` turns that into its fallback. Mostly-portable modules (overlay, claude, chat, local, llama, hooks, fsx, log, updater) use `#[cfg(windows)]` guards, `crate::nowindow::NoWindow` for helper processes, `crate::mac::sys` (sysctl, statfs) for system facts and `crate::mac::input` (CoreGraphics) for the mouse and Control key. On a Mac the island is an Accessory app (no Dock icon) over the screen's visible frame, so the top anchor sits under the menu bar. `src/core/platform.ts` decides what the UI offers: catalog field `mac: 'soon' | 'never'`; the island never starts, setup never picks, and the Activities page labels ("Coming to Mac", "Windows only") what a Mac cannot run. Mac builds: `.github/workflows/macos.yml` (compile check, universal `.dmg`, a 25 s smoke run with a screenshot). Since 0.3.0 the `.dmg` from the release commit's run is attached to each release as `Island.dmg` (Moss tried the first Mac build on a MacBook and it worked); it is ad-hoc signed, not notarized, so the README says how to open it the first time. From 0.3.0 on a Mac updates itself (see Updates); the `update-test` job runs the updater's tests on a Mac, one of which installs a real disk image made with hdiutil over a test Island.app. Spec and plan: `docs/superpowers/`.

## Land (file sharing)

Land sends files between computers on the same network that run Island, like AirDrop (Moss named it: "is-land"). Drag files onto the pill and the island opens on Land's card: the files, the computers nearby as avatars, and Send. The other computer's island asks first (who, what, how big, a two-minute countdown); accepted files land in its Downloads. Both sides show progress on the pill, the card and the avatars; the bot reacts (uploading and downloading moods, `land-sent` and `land-received` moments).

**In the island.** Only the island window takes file drops (`overlay.rs`: `drag_and_drop(label == LABEL)`), and only where it takes the mouse, so a drop anywhere else still lands on the app underneath. Windows asks the window under the pointer for a drop target, and wry registers its target once, on the child windows that exist when the page is made. The island's page is made hidden at startup, before WebView2 creates the windows that end up under the pointer (`Chrome_WidgetWin_1`, the legacy render window, the D3D window), so until 0.2.8 those had none and every file dragged onto the pill got the "not allowed" cursor. `share_drop_target` gives each of them wry's own target (read from the `OleDropTargetInterface` window property OLE keeps), on the main thread; the poll re-checks every 2 s, since WebView2 may make them again. `onFileDrop` (`native.ts`) turns Tauri's drag events into CSS px. While files hover, the pill shows the hint of the first activity whose `accepts()` answers; a drop goes to its `drop(paths)` and the open island shows that activity's own card instead of Control Center (`ActivityContext.openCard`, `Island.cardFor`, `sheet()` with reason `open`; the card's grid button goes back). Avatars are the `people` block in `sheet.ts`.

**On the pill.** Land is always there as a little icon (Moss, 2026-10-16): its status at rest is `chipOnly`, so it is a chip beside whatever has the pill (last in the row, ranked above the other chips so they fold into "+N" first) and, with nothing else on, the pill holds just the chips; it never becomes the pill's own content at rest. A click on the icon opens Land's card (`ChipView.action`). Hovering it and pressing Ctrl+V opens the card with what was copied, ready to send: while the pointer rests on the icon the island asks Rust to hold Ctrl+V as a hotkey (`island_paste_arm`; never while the island takes the keyboard), so the press reaches Island instead of the app in front (nothing is pasted twice, nothing takes the focus); `land-paste` then reads the clipboard (`clipboard_paste`: files copied in Explorer, else text) and stages it. Control Center has a Land tile only with Activities › Land › Tile in Control Center on (off by default).

**In Rust (`src-tauri/src/land/`).** Product logic stays in `src/activities/land.ts`; Rust finds computers, encrypts and moves bytes. `mod.rs` is the service and its commands; `wire.rs` the keys, frames and the Noise handshake; `discovery.rs` the packets and the loops that send them; `files.rs` what a dropped path holds and where things land; `transfer.rs` the offer, a transfer's state and what waits; `send.rs` and `receive.rs` the two sides; `share.rs` sharing with a phone; `tests.rs` the tests.

- *Identity*: an X25519 key pair made on first use (`<data dir>/land.key`). A device's id is the first 8 bytes of SHA-256 of its public key, so nobody can claim another device's id.
- *Finding computers*: UDP port 47821. Packets go to the multicast group 239.255.77.77 (TTL 1) through every interface, to each subnet's broadcast address and to 255.255.255.255: `{"land":1,"t":"here"|"ask"|"bye","id","name","os","port","key"}`. A packet whose id is not its key's is dropped, and so is one from outside this computer's subnets (private or link-local addresses only; a VPN's /31 or /32 is no local network). Each Island asks at start and says "here" every 30 s; an ask gets a direct answer (at most every 2 s per asker); "bye" when Land turns off. The card asks again every 4 s while open. A computer not heard for 95 s, or refusing a connection, leaves the list.
- *A transfer*: TCP to the port the receiver announced, then a Noise `XX_25519_ChaChaPoly_BLAKE2s` handshake (prologue `island-land/1`). The sender checks that the receiver's key is the one it announced. Frames are a u16 length and a Noise message; the first decrypted byte says what follows (1 part of a JSON message, 2 its end, 3 file bytes). `offer {from, os, files: [{name, size}]}` → `accept` or `decline {why: declined | timeout | busy | space | bad}` → the files back to back in frames of up to 60 KB → `done` → `saved`. Either side can send `cancel` (or `error`) at any time.
- *Receiving*: nothing is written before Accept. Names are cleaned (no separators, `..`, characters Windows refuses or device names like CON; 150 characters at most); every dropped folder becomes a new folder in Downloads ("Photos (1)" if "Photos" exists). Files are written as `<name>.landing` and get their name with a hard link, which never replaces an existing file ("photo (1).jpg"). Received files are marked as coming from another computer (Zone.Identifier ZoneId=3 on Windows, `com.apple.quarantine` on a Mac), like browser downloads. Not enough room in Downloads declines; at most 3 offers wait at once, one per computer, and a computer just declined is turned away for 15 s.
- *To the island*: events `land-peers` (the list) and `land-transfer` (one transfer: state, bytes, the dropped items, what was saved; progress at most every 150 ms). Commands `land_start` (on, or a new name or visibility), `land_stop`, `land_scan`, `land_send`, `land_answer`, `land_cancel`, `land_stage` (names, sizes and file counts of dropped paths).

**First start.** Listening makes Windows ask to let Island through the firewall (allow it on private networks), and a Mac ask for local network access (`src-tauri/Info.plist`). The island says why at that moment ("Land is on" card). Activities › Land: the name others see, and whether this computer takes files (off: it can still send).

**Friends on other networks (`src-tauri/src/anywhere.rs`).** The plan and its slices are in `docs/LAND-ANYWHERE.md`. Slices 1–3 are done: Islands become friends from anywhere and send each other files.

- **Nearby friends.** With Land anywhere on, the announcement also carries `ak` (the friend key) and `aks` (its signature over the packet's Land key; `Hello::decode` drops a claim that fails it). A friend nearby shows once, as the computer nearby, and gets files over TCP. A nearby Island can be added without a code (`land_friend_add_nearby`, from Activities › Land).
- **Resume after a drop** (both kinds of transfer). Offers carry `tid` and each file's `mtime`. If the connection drops after Accept, the sender pauses and tries again (2 s doubling to 5 min, for 30 min; `Timing`), and the receiver keeps the `.landing` pieces for 2 h (`Paused`, keyed by sender and `tid`). The same transfer coming back is accepted without asking: `{t:"accept", have:[...]}`, the bytes already on disk, which the sender seeks past. Files changed meanwhile: asked again. A paused receive the user cancels removes the pieces and turns the comeback away for an hour. State `paused` in `land-transfer`.
- **Friends who are away.** A friend's Island that can't be reached makes the send wait (`queued`), kept in `<data dir>/land-queue.json` across restarts. Any connection from that friend wakes it (`kick`), and so does a try every 2 minutes; a starting Land says hello to its friends after 5 s. It gives up after 3 days. Waiting sends stay off the pill; the card says "Sends when Alex is online".
- **Relays.** n0's free relays (about 1.15 MB/s through them; a direct path is as fast as the networks). Moss chose not to run a relay server, and the "Your relay" setting went in 0.3.0; the tests still meet through a relay of their own (`Relays::Local`).
- **Text and links.** An offer may carry `text` and no files (`land_send_text`; at most 20 000 characters, control characters dropped but line breaks), with the same consent, limits and waiting for friends as files. The receiver's card shows the text with Copy, Open (when it is one web address) or Decline; taking it answers the offer. An Island before 0.3.0 declines it as `bad`, and the sender says they need to update.
- **Any phone** (`land/share.rs`, `land_share_start`, `land_share_stop`). Send to a phone serves what was dropped (or the text) at `http://<this computer's private address>:<random port>/<128 random bits>/` for 15 minutes or until Stop; the card shows the address as a QR code (`qrcode` crate, the `qr` block in `sheet.ts`), which the phone's camera opens in its browser. Only addresses on this computer's subnets get an answer. The page lists the files with Save (`attachment`), opens images, PDFs, audio and video inline (with byte ranges, which Safari needs for video) and serves anything that could run in a page (HTML, SVG, scripts) only as a download. Plain HTTP, since a phone has no way to trust a certificate made here: someone watching the same Wi-Fi could see what goes, so the card says to stop once it's done. `land-share` reports the first read of each file and the end. Many school and café networks keep devices from seeing each other; then the phone can't open it.
- **Transfers with friends.** Same exchange as nearby, over one QUIC stream on `island-land/2` instead of TCP + Noise (`Wire::Plain`; QUIC already encrypts and proves the key). `Running::send` takes a nearby computer's id or a friend's key. `send_far` dials the friend; `receive_far` takes their connection from `Far::land_connections`. Transfers report `via` (`lan`, `direct`, `relay`). The card lists friends after the computers nearby, with "Online" from `land_friends_online` (each friend dialled with a 3 s limit; a connection without a stream is only that check).

- **Endpoint.** With the switch on (Activities › Land, default on), Land also starts an iroh 1.3 endpoint. Its key (Ed25519, `<data dir>/land-anywhere.key`) is the Island's address anywhere. iroh dials by key over QUIC: straight through both routers when it can (hole punching, UPnP/NAT-PMP), through n0's free relays when it can't, with n0's DNS key lookup (`presets::N0`). It is end-to-end encrypted either way.
- **Who gets in.** Connections on `island-land/2` are let in only for friends' keys. Any other key is closed (code 403) once the handshake proves it. Anyone may use `island-friend/1`, the friend request.
- **Codes.** `land:` plus 56 base32 characters (version, key, 2 check bytes); pasting is forgiving, typos are caught.
- **Friends.** Kept in `<data dir>/land-friends.json`, owned by Rust. Requests, their limits and their wire format: LAND-ANYWHERE.md slice 2. The island shows a request like a file offer (urgent, Block / Not now / Add). Activities › Land has the code, Add a friend, and the list with Remove / Block.
- **To the island.** Events `land-friend-ask` and `land-friends`. Commands `land_me`, `land_friends`, `land_friends_online`, `land_friend_add`, `land_friend_answer`, `land_friend_remove`; `land_start` takes `anywhere`.
- **Tests.** In `anywhere.rs` and `land/tests.rs`. Three ignored ones go through n0 for real: `found_by_key_through_n0`; `files_reach_a_friend_through_n0`, which sends 2 MB the normal way and relay-only; and `ask_the_island_running_here`, which asks the Island running on this computer and gives up after its request shows (`cargo test --lib anywhere::tests::ask_the_island_running_here -- --ignored --nocapture`).

**Tests.** `land.rs` covers the packets, names, the local-network rule and whole transfers over loopback (consent, decline, cancel, a key that does not match, never overwriting); two ignored tests run against real things: two devices finding each other on this computer's network, and offering a file to the Island running here (`cargo test --lib land::tests::offer_the_island -- --ignored --nocapture`). `test/land.test.ts` covers the activity. Browser preview: `/?land` (card after a drop), `/?land=drag`, `/?land=ask`, `/?land=send`.

## Phone

Both directions use what is already there instead of a companion app: an iPhone app cannot read other apps' notifications, so the phone's side is Phone Link's Bluetooth sharing.

- **To the phone** (`src-tauri/src/phone.rs`, `phone_push`): one JSON POST to `https://ntfy.sh/` per push (`topic`, `title`, `message`, an emoji `tag`, `priority`); JSON because ntfy's header form only takes ASCII. The topic (`island-` and 24 hex characters, made when Settings › Notifications › Send to my phone is first turned on) is the only secret. `ActivityContext.notify(title, body, phone?)` shows a Windows notification and pushes; `push(title, body, look)` only pushes. Quiet holds both.
- **Answering from the phone** (Settings › Notifications › Answer Claude from my phone, off by default, Windows): a permission request that waits in the island goes out with Allow and Deny buttons (ntfy's `http` actions, which the iPhone app does too). Each posts its word and a one-time 128-bit code to a second random topic (`general.phoneReplyTopic`); `phone_listen` streams that topic (`/json?since=…`) for 130 s per push and hands each message to the island as `phone-reply`, and the Claude activity answers the request the code was made for, once. With Windows Hello asked before Allow, the phone gets only Deny. Anyone who can read the push topic could tap the buttons too, which the setting says. Checked against ntfy.sh on throwaway topics (2026-10-16): the actions are accepted as sent and the stream's messages are what `reply_in` reads.
- **Claude's moments** (`src/activities/claude/pushes.ts`): finished (with the last message), error, a question (with numbered options), a permission request (what it wants to run), needs you, and "your turn" after a quiet spell. Claude Code reports one moment several ways (PreToolUse and PermissionRequest for a question, then the permission_prompt Notification, then polling), so `PushGate` sends each once per chat. Activities › Claude Code › Send to my phone turns them off.
- **From the phone** (`src-tauri/src/phonelink.rs`, `src/activities/phone.ts`): Phone Link shows the phone's notifications as Windows toasts. `UserNotificationListener` (allowed for unpackaged apps when Settings › Privacy › Notifications lets apps read notifications) is polled every 2 s while the Phone activity runs; only toasts from `Microsoft.YourPhone_*` pass, as `phone-note` events (an iPhone's lines: app, sender, text). The activity shows each for 6 s and skips the ntfy app's, which are Island's own pushes coming back. Nothing is stored.

## Island on your phone

A website (`phone/`, published at https://islandphone.vercel.app, a Home Screen web app on the iPhone) that shows the island live and acts on it from anywhere. Design: `docs/superpowers/specs/2026-10-22-island-phone-design.md`; the messages both sides speak: `src/remote/protocol.ts`.

- **It draws the island's own data with the island's own code.** The island already turns what it draws into data: the pill as a `MirrorFrame` (Duplicate mode's), cards and Control Center as `SheetView`s whose buttons carry `act:<activity>:<name>`. The phone draws them with `PillRenderer`, `SheetRenderer` and `BubbleView` and island.css, so every activity works on the phone without phone-only code, and a tap goes back as the same action string, run through `handleAction`. Upright the bot sits above a centred pill; sideways beside it, as on the PC.
- **The connection.** The phone runs iroh 1.3 compiled to WebAssembly (`phone/wasm`, `phone/web/src/link`), which in a browser always goes through n0's relays over WebSocket; QUIC/TLS stays end to end between the phone and the PC. The island keeps its own endpoint for phones (`src-tauri/src/remote/`, key `phone-endpoint.key`, ALPN `island-phone/1`), separate from Land's, running only while a phone is paired or being paired. One control stream of JSON lines (at most 1 MiB each), plus a stream per file.
- **Pairing.** Settings › Your phone › Pair a phone shows a QR code of `islandphone.vercel.app/#pair=<base64url JSON>` (the island's EndpointId, its relays, a one-time code good for 10 minutes and 5 tries, the computer's name). The phone makes its own key (kept in its storage), dials, and says `pair`; later connections say `hi`, and only paired keys (`phones.json`) get past it. Removing a phone cuts it off at once (`bye`).
- **The hub** (`src/remote/hub.ts`) sends each connected phone a `hello`, its pill and its view (an urgent card first, else Control Center packed for the phone's width or the activity card the phone opened), each at most 8 times a second and only when it changed. A phone may press only what it was last shown, with the argument it was shown with (`actionsIn`), plus Quiet; never grid arranging or other `island:*` actions. With Windows Hello asked before Allow, Claude's Allow is stripped from what phones see. An activity that opens its card during a phone's tap (`ctx.openCard()`) opens it on that phone, not the PC.
- **Phone ↔ PC.** Files from the phone land in Downloads with Land's rules (never overwritten, marked as from another computer) and show like Land's deliveries; text goes to the clipboard and Land's text card; `clip-get` answers with the PC clipboard; `lock` locks the PC. Land's card lists connected phones as targets (`remote_send_file`, a `text` line).
- **Notifications.** The island makes a VAPID key; the Home Screen app subscribes with it and sends the subscription (`push-sub`); wherever Island pushes to ntfy (`toPhone`) it also sends an RFC 8291 encrypted Web Push to subscribed phones (`remote_push`, only to Apple's, Google's, Mozilla's and Microsoft's push services). A phone takes notifications from one PC at a time (one subscription per web app).
- **iOS 26.** The site has no `apple-mobile-web-app-status-bar-style` tag: since iOS 26.1 a `black-translucent` Home Screen app gets a dark gradient over its top (WebKit bug 317153), so the status bar takes the page's colour and sits above the page. An install made before that still runs under the status bar, and its island starts below the gradient.
- **Terminals** (part 2, `docs/superpowers/specs/2026-10-28-phone-terminal-claude-screen-design.md`). Island owns pseudo-terminals (`src-tauri/src/term/`, portable-pty: ConPTY on Windows), at most 8, each with a 256 KiB replay buffer; they keep running with no phone attached. A phone opens one on its own bi-stream (`src-tauri/src/remote/terms.rs`): a `term` header line, a `term-ok`/`term-error` line, then frames both ways (kind u8, length u32 BE, at most 64 KiB: data, resize, exit, title); the replay comes first. `term-list`/`term-kill`/`terms` are control lines Rust answers itself. Off until Settings › Your phone › Terminal from your phone (and off while Windows Hello guards Allow); the island says when a phone opens one.
- **Claude chat.** Claude's card on a phone (`reason: 'open'`) lists chats and opens one: its last 12 messages and a "Message Claude…" box that is always there. `messageChat` (src/activities/claude) routes a message: a chat in an Island terminal gets typed into it; a live terminal chat gets `claudeInject`; a VS Code chat (or a closed chat) continues in an Island terminal running `claude --resume <id> [--fork-session] <text>` (fork while the VS Code panel still holds it); a new chat runs `claude <text>` in the folder. Its Open on the PC moves it to VS Code.
- **Screen.** `hello.screen` says whether Chrome Remote Desktop's `chromoting` service runs; the phone's Screen button navigates to remotedesktop.google.com/access, which iOS shows in the Home Screen app's own browser with a Done button back (Google's site can't be framed).
- **Build and publish:** `node scripts/phone.mjs wasm|dev|build|deploy|e2e` (clang, wasm-bindgen 0.2.129 and wasm-opt in `%LOCALAPPDATA%\windows-dynamic-island\tools`; the wasm build's target dir is `target-phone` there). `?demo` runs the site with a pretend PC (`&two`: a second one).

## Build notes

- The Cargo target directory lives outside OneDrive (`%LOCALAPPDATA%\windows-dynamic-island\target`, set by `scripts/tauri.mjs`), because OneDrive would otherwise sync several GB of build output. A bare `cargo test`/`cargo build` in the repo uses `./target` instead (4.8 GB of it was found and deleted on 2026-10-09): set `CARGO_TARGET_DIR` to the folder above first.
- `npm run dev` serves the island in a browser with mocked native data (fast UI work). `npm run tauri dev` runs the real app. `npm run release` builds the exe and copies it to `release/`.
