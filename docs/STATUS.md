## 2026-10-06, 15:20 — where the CPU went

Measured, not guessed. Island settled, Activities window open in every reading:

| | Rust (Island.exe) | WebView2 renderers |
|---|---|---|
| before | 11.3% | ~44% |
| after | **5.5%** | **21%** with the comet, **1.6%** with the glow off |

- **The glow is the whole story.** The island is a see-through window the size of the
  work area; anything that animates inside it makes Windows blend that whole window
  again every frame. The drawing itself is nearly free: the same comet in a normal
  Chromium window costs 1.4%. Rewriting it from per-frame JavaScript (SVG dashes +
  a blur filter) to a GPU-turned cone behind a ring mask took it from ~40% to ~20%,
  and removing the blend mode and the halo blur changed nothing (25% vs 21% = noise).
  Whatever draws it, a continuously moving glow in this overlay costs about a fifth
  of a core. Settings › Border glow › Off is the cheap setting, and its help text
  now says so.
- **Rust halved** by caching the overlay's position and scale (it was asking the
  window 62 times a second) and by polling the cursor at 100 ms unless it is within
  180 px of the island. No click is missed: the poll reads the "pressed since last
  check" bit, not just the current button state.
- Claude's session scan 1.5 s → 3 s and desktop chats 3 s → 8 s; hooks already report
  changes instantly. The system activity was left alone — it paces itself already
  (5 s idle, 2 s while hot) and my first change broke that.
- No leaks: the island page holds 409 DOM nodes, a 7 MB JS heap and 1 animation,
  all flat over 37 s.

Also in this build: white accent colour; the Control Center grid, calendar source
switch and glow all still untested on screen by Moss.
